# SimpleSchedule — сборка и устройство проекта

Нативное приложение для macOS 27: Swift 6, SwiftUI и AppKit, с делами, расписанием университета и отдельным расширением WidgetKit для рабочего стола. Значок календаря находится в области приложений строки меню; нажмите на него, чтобы открыть панель. Дела и сохраненное расписание доступны локально без учетной записи. Расписание ИРНИТУ можно загрузить с официального сайта по явному действию пользователя; фонового обновления нет.

Команды ниже выполняются из корня репозитория. Имена Xcode-проекта, схемы и локального пакета пока сохраняют техническое название `Calendar`. Готовые DMG опубликованы в [Releases](https://github.com/pouqwyggad1/SimpleSchedule/releases); пользовательская инструкция находится в [README](../README.md).

## Сборка в Xcode

1. Откройте `Calendar.xcodeproj` в полном Xcode с поддержкой Swift 6 и SDK macOS 27. Минимальная версия системы — macOS 27.0. Command Line Tools не заменяют полный Xcode для установки виджета.
2. Выберите схему **Calendar**, устройство **My Mac**. Схема собирает основное приложение, `CalendarWidget.appex` в `Calendar.app/Contents/PlugIns` и службу `ScheduleFetcher.xpc` в `Calendar.app/Contents/XPCServices`.
3. Для **Calendar**, **CalendarWidget** и **ScheduleFetcherXPC** в **Signing & Capabilities** выберите одну Team и действительную подпись. Для приложения и виджета Team должна поддерживать **App Groups**. Оставьте **App Sandbox** у всех трех targets; сетевой **Outgoing Connections (Client)** разрешен только у **ScheduleFetcherXPC**, без App Groups у этой службы. Для рабочей пары приложение/виджет подписи **Sign to Run Locally** недостаточно.
4. Проверьте одинаковую App Group у **Calendar** и **CalendarWidget**; у **ScheduleFetcherXPC** ее быть не должно. В проекте используется `$(TeamIdentifierPrefix)ru.local.GoldenGateCalendar.shared`: Xcode подставляет префикс выбранной Team. Совпадать должны разрешение App Groups и значение `PlannerAppGroupIdentifier` в `Info.plist` приложения и расширения. Если меняете идентификаторы для своей Team, сохраняйте это соответствие; bundle identifier расширения должен оставаться дочерним для основного приложения.
5. Нажмите **⌘R** и сначала откройте основное приложение: оно подготавливает собственное общее хранилище и переносит туда прежние локальные данные, если они есть. Значок календаря появится в строке меню. Если область скрыта вырезом экрана или переполнена, освободите место штатными средствами macOS.
6. В системной галерее виджетов рабочего стола найдите **Календарь и дела** и добавьте средний виджет. Расширение поддерживает размер `.systemMedium`. Его установкой и запуском управляет WidgetKit; приложение не устанавливает виджет на рабочий стол самостоятельно.
7. Для постоянного использования соберите Release и вручную переместите `Calendar.app` в «Программы» или `~/Applications` **до** настройки автозапуска. Запускайте приложение из постоянного расположения; расширение остается внутри пакета.

В проекте нет пакетов Swift Package Manager, CocoaPods, скриптов загрузки, серверов и внешних ресурсов. Компилятор, SDK и сертификаты/профили подписи должны быть установлены заранее. Регистрация Team и подготовка подписи в Xcode — настройка среды разработчика; для сборки без сети эти действия нужно завершить заранее. Сборка не загружает зависимости. Без аккаунта и с ручным обновлением обычный запуск и чтение локальных данных не требуют сети. Вход в аккаунт включает фоновую синхронизацию; автоматическое обновление расписания включается отдельно в настройках. Загрузка списков и импорт ИРНИТУ требуют подключения.

## Сборка без полного Xcode

Если установлены современные Command Line Tools, из корня проекта:

```sh
./scripts/build-offline.sh
```

Готовый пакет: `build/Calendar.app`. Это самостоятельная локальная сборка **приложения со встроенной XPC-службой импорта, без виджета и App Groups**. Скрипт компилирует исходники Swift, сначала подписывает `ScheduleFetcher.xpc` с отдельным `ScheduleFetcher.entitlements`, затем пакет приложения с `Calendar-Local.entitlements` и проверяет разрешения обоих компонентов. Основное приложение не получает сетевого разрешения. Скрипт **не запускает** приложение и не регистрирует автозапуск.

```sh
./scripts/build-offline.sh --universal
```

Этот вариант содержит `arm64` и `x86_64`. Сама работоспособность на Intel требует Mac с совместимой macOS 27. Для запуска откройте пакет в Finder или выполните:

```sh
open build/Calendar.app
```

Отдельная проверка исходников расширения:

```sh
./scripts/build-offline.sh --check-widget
# При необходимости обе архитектуры:
./scripts/build-offline.sh --check-widget --universal
```

Она компилирует и линкует код с ограничениями App Extension в `build/widget-check/CalendarWidget`, не заменяя пакет приложения. Это **не установленный и не работающий виджет**: здесь нет извлечения App Intents metadata, подписанной App Group, встроенного `.appex` и регистрации WidgetKit. Для функционального виджета выполните сборку в полном Xcode с Team по инструкции выше.

Отдельная сборка диагностического XPC-хоста, которая не заменяет основной пакет:

```sh
./scripts/build-offline.sh --check-fetcher
```

Она собирает и локально подписывает `build/fetcher-check/FetchCheck.app` со своей встроенной службой, но не запускает его. Наличие этого пакета подтверждает только сборку; фактический запрос, запрет сети в хосте и завершение службы проверяются отдельно и отражаются в отчете. Диагностический хост не входит в поставляемое приложение. Для явной проверки выполните `build/fetcher-check/FetchCheck.app/Contents/MacOS/FetchCheck --chain`: три HTML-запроса, разбор и сохранение в отдельную временную базу с повторным открытием. Рабочая база приложения не открывается. Режим `--verify-isolation /raspisanie` дополнительно проверяет отказ прямой сети у хоста; `--policy-tests` работает без сети.

## Использование

Ниже описан режим дел. Кнопка с академической шапочкой рядом с шестеренкой переключает панель на расписание университета.

- **Месяц / Неделя / День** используют одну выбранную дату. Переключение вида ее сохраняет. При новом запуске выбирается сегодня.
- Поле даты позволяет менять день, месяц и год; подпись «Дата» перед ним скрыта. Непосредственно слева находится кнопка **Группы** для управления группами. Кнопка с календарем справа открывает переход к произвольной дате (годы 1–9999). Несуществующую дату сохранить нельзя. Стрелки сдвигают месяц, неделю или день; **Сегодня** возвращает к текущему дню.
- Справа от стрелок и «Сегодня» находятся кнопки групп с названиями и цветными метками. Если места недостаточно, оставшиеся группы доступны в меню **+N** перед кнопкой **Группы**. Список обновляется при создании, переименовании, перекрашивании и удалении групп.
- Нажатие на кнопку группы или ее пункт в **+N** открывает **все дела этой группы за все даты**. Выбранная кнопка подсвечивается; для скрытой группы подсвечивается **+N**, а пункт меню отмечается галочкой. Невыполненные дела идут первыми, внутри каждого статуса — по дате. Повторное нажатие на ту же группу возвращает прежний вид календаря и выбранную дату. Другая группа заменяет только страницу группы. **К календарю** или переключатель **Месяц / Неделя / День** также закрывает страницу группы, сохраняя дату.
- **Без группы** всегда доступна среди этих кнопок или в **+N**. Она показывает все дела, у которых не назначена группа, за все даты. Это виртуальный раздел с нейтральной меткой: его нельзя переименовать, перекрасить или удалить через управление группами. Повторный выбор возвращает прежний календарь; добавление дела из этого раздела оставляет в форме **Без группы**.
- В месяце выберите день: его дела появятся справа. Кольцо вокруг числа отмечает сегодня, фон и рамка ячейки — выбранный день. Цветные точки показывают представленные группы, `+N` — оставшиеся; полая точка обозначает дела без группы.
- В неделе семь колонок с понедельника по воскресенье. Суббота и воскресенье красные. Каждая колонка прокручивается отдельно, ее заголовок остается на месте. Нижний **+** добавляет дело на дату колонки.
- Верхний **+ Добавить** создает дело на выбранную дату. На странице группы эта группа уже выбрана в форме; ее можно изменить. Название обязательно; группа и заметка необязательны. Группу можно создать сразу в форме дела.
- Нажмите на название дела для редактирования. Кружок меняет выполнение. Выполненные дела зачеркнуты и идут после невыполненных. Меню **…** содержит редактирование и удаление с подтверждением.
- Кнопка **Группы** слева от поля даты открывает управление группами; меню шестеренки содержит **Настройки** и завершение приложения. У группы можно менять название и цвет: есть восемь быстрых образцов и нативный выбор произвольного цвета. Удаление группы с подтверждением сохраняет все ее дела с меткой **Без группы**. Если удалена открытая группа, панель возвращается к прежнему виду календаря и дате.
- Повторный левый клик по значку строки меню скрывает панель; следующий показывает ее снова. Открытая форма и ее черновик при этом сохраняются. Панель остается открытой при переключении рабочих столов. Клик вне панели или **Escape** скрывает ее, когда нет открытой формы. В меню шестеренки и по правому клику на значок есть **Завершить приложение**.

## Расписание университета

Нажмите кнопку с академической шапочкой (**Расписание университета**) слева от шестеренки. Она подсвечивается, а заголовок панели меняется на **Расписание**. Кнопки групп, управление группами и списки дел скрываются; панель показывает занятия. Повторное нажатие возвращает режим дел. Выбранная дата и переключатель **Месяц / Неделя / День** общие для обоих режимов: смена режима сохраняет их. Поле даты, переход к произвольной дате, стрелки и **Сегодня** работают и в расписании.

- В **Месяце** ячейка показывает число пар и общий диапазон от начала первой до окончания последней, например **2 пары · с 08:30 до 13:30**. В пустой ячейке остается только число. При выборе дня справа открываются его занятия.
- В **Неделе** семь колонок с понедельника по воскресенье; выходные красные. Под заголовками находятся карточки занятий, упорядоченные по времени начала. Каждая колонка прокручивается отдельно, заголовки остаются видимыми. Нижний **+** подставляет дату своей колонки.
- В **Дне** показаны полная дата и карточки с предметом, временем, видом занятия, подгруппой, кабинетом, руководителем и домашним заданием. Академическая группа на карточке не отображается. Необязательные пустые поля в карточке скрыты. Для пустого дня есть сообщение **На этот день пар нет** и добавление пары.
- Верхний **+ Занятие** открывает форму на выбранную дату. **Предмет**, дата, начало и окончание обязательны. **Вид занятия**, **Подгруппа**, **Домашнее задание**, **Кабинет** и **Руководитель** необязательны. При создании пары и после изменения начала окончание подставляется как начало плюс длительность из настроек (по умолчанию 90 минут); его можно исправить вручную. Открытие существующей пары сохраняет ее время до изменения начала. Пустой предмет и окончание не позже начала блокируют сохранение; время задается в пределах одних суток.
- Тонкая рамка карточки обозначает вид занятия: лабораторная работа — желто-оранжевая, практика — зеленая, остальные занятия — синяя. Название вида также остается текстом. Цвета пользовательских групп от этого не меняются.
- Нажатие на карточку открывает редактирование. Можно изменить предмет, дату, время и дополнительные поля. Меню **…** позволяет редактировать или удалить пару; удаление требует подтверждения. Изменения обновляют карточки и сводку месяца.

При переключении между делами и расписанием общие элементы остаются на своих местах: переключатель видов по центру, стрелки, дата, добавление, месячная сетка и правая панель имеют одинаковые слоты и размеры. Скрытые кнопки групп сохраняют свое место, не отображаясь в расписании. На узкой панели шапка всегда использует две строки, а обновление обозначено иконкой; загрузка и ошибка не сжимают плитки календаря.

Формы дела, занятия, группы, настройки и переход к дате используют одинаковые внешние отступы 24 pt, промежутки 16 pt между заголовком, содержимым и кнопками; нижние кнопки имеют общий размер 100 × 28 pt. Прокручиваемое содержимое форм ограничено своей областью.

Каждая запись — отдельное занятие на конкретную дату. Занятия сохраняются отдельно от дел и пользовательских групп; удаление группы не затрагивает расписание.

### Импорт с сайта ИРНИТУ

Источник — [официальное расписание ИРНИТУ](https://www.istu.edu/raspisanie). В **Настройки → Расписание ИРНИТУ**:

1. Нажмите **Загрузить институты** (после первой загрузки — **Обновить институты**). Список разбирается из HTML сайта и сохраняется локально.
2. Выберите институт: это явное действие загружает его группы. Кнопка **Загрузить группы / Обновить группы** позволяет повторить загрузку для текущего института.
3. Выберите свою академическую группу. В настройках есть один выбор **Подгруппа**: номера появляются после обновления расписания и берутся из карточек этой группы на сайте, включая обе недельные альтернативы. Готового списка номеров и отдельного поля ввода нет. **Все подгруппы** показывает полный список активных занятий группы; при выбранном номере остаются общие пары и пары этой подгруппы.
4. Задайте **Длительность пары** от 1 до 360 минут (исходно 90). Настройки сохраняются сразу. Закройте настройки и в режиме расписания нажмите **Обновить расписание** слева от переключателя **Месяц / Неделя / День**.

Кнопка обновления видна только в расписании. В месячном виде загружаются недели, покрывающие видимую сетку месяца (до шести), а в недельном и дневном — одна неделя выбранной даты. Это одна ограниченная операция, которая может выполнить несколько последовательных HTML GET. В ручном режиме переключение дат и видов, открытие панели и обычный запуск не загружают расписание. Выбранное в настройках автоматическое обновление выполняется отдельно от навигации. Во время загрузки в кнопке появляется индикатор; повторное нажатие отменяет обновление. В настройках для загрузок доступна **Отмена**. Ошибка открывается во всплывающем сообщении рядом с кнопкой обновления. Постоянная строка «Расписание обновлено. Добавлено…» на календаре не показывается. Сохраненные списки и занятия доступны без сети, а их обновление требует подключения.

Все активные занятия всех подгрупп загружаются сразу, независимо от выбранного номера. Его изменение в настройках сразу перестраивает месяц, неделю и день по сохраненным данным, без повторного запроса. Общие пары не скрываются. Номера подгрупп и их выбор сохраняются локально.

Сайт показывает серые неактивные недельные альтернативы вместе с текущими парами. Парсер повторяет выбор активных карточек по классу внешнего блока недели и исключает серые альтернативы и `card-unactive`; текстовая подпись четности и вычисление от 1 сентября не используются. Данные воспроизводимого сравнения приведены в [описании HTML-фрагментов](../Fixtures/ISTU/README.md). Если период был импортирован старой версией, нажмите **Обновить расписание** для этого периода: простое переключение режима не перезагружает уже сохраненные записи.

Импорт разбирает дату, начало, предмет, буквальное название вида занятия (лекция, практика, лабораторная работа и другие), преподавателя, подгруппу и аудиторию. Окончание рассчитывается как начало плюс выбранная длительность. Название академической группы служит выбору источника и не выводится на карточке. Домашнее задание вводится вручную.

Повторное обновление сопоставляет занятия с предыдущим снимком источника. Измененные пользователем поля и домашнее задание сохраняются; остальные поля получают актуальные значения сайта. Ручные занятия не удаляются и не заменяются. Занятие, вручную удаленное после импорта, не возвращается при повторной загрузке той же записи. Если занятие исчезло с сайта, оно удаляется только в подтвержденных загруженных днях выбранной группы и только при отсутствии ручных правок или домашнего задания. Другие даты и группы остаются в локальной базе; импортированные занятия показываются только для выбранной академической группы. Фильтр подгруппы применяется также к ручной записи, если ей задана подгруппа.

Изменение длительности пересчитывает сохраненные импортированные окончания, которые пользователь еще не менял вручную. Ручные занятия сохраняют установленное время. Если вычисленное окончание вышло за пределы суток или стало некорректным, изменение отклоняется с сообщением. Неполный период допустим: приложение пробует недели видимой сетки и одной записью применяет все подтвержденные дни, даже если отдельные страницы недоступны или расписание обрывается. Дни, которых сайт не вернул, сохраняют прежние данные; отсутствие дня не считается пустым расписанием. Известный ответ сайта «Не обнаружено занятий с заданными характеристиками» не вызывает ошибку и не очищает базу. Если не удалось получить ни одного подтвержденного дня и есть настоящая сетевая ошибка или неизвестная разметка, показывается ошибка. Отмена и смена источника во время загрузки отменяют запись всей операции. Парсер зависит от структуры сайта; при ее изменении может потребоваться обновление приложения.

## Виджет рабочего стола

Виджет показывает один выбранный день, его дату и дела. Переключение панели на расписание сохраняет это назначение виджета: он продолжает показывать список дел. Кружок выполнения использует цвет группы; завершенные дела зачеркнуты и идут после незавершенных. Длинные названия ограничены доступным местом. Если все дела не помещаются, **Еще дел: N** открывает полный день в приложении.

Стрелки перелистывают дни. **Сегодня** включает следование текущему дню: в timeline заранее подготовлена запись на ближайшую полночь. После ручного выбора даты или перелистывания день остается фиксированным до следующего нажатия **Сегодня**. Поле даты справа внизу открывает выбор даты **виджета** в приложении; оно не меняет выбранную дату и режим календарной панели. Нажатие на крупную дату, название дела или **Еще дел** открывает выбранный день в режиме **День** основного приложения.

Выполнение дел и перелистывание используют локальные App Intents. Обычная отметка выполнения не требует открытия панели. Приложение и виджет обращаются к одному собственному хранилищу; записи защищены общей межпроцессной блокировкой и атомарной заменой файлов. Все экземпляры виджета используют одну сохраненную дату. Настройки темы и прозрачности относятся к панели приложения; оформление виджета определяет среда WidgetKit.

Обновления запрашиваются после действий, но момент перерисовки определяет macOS и ее бюджет WidgetKit. Если общий контейнер или данные недоступны, виджет показывает ошибку вместо достоверно пустого дня. В текущем окружении без полного Xcode и подписанной Team можно проверить компиляцию и локальную логику; появление в галерее, выполнение App Intents и визуальное поведение установленного виджета требуют проверки на целевом Mac.

## Оформление и автозапуск

Размытие создает `NSVisualEffectView` позади содержимого окна. У стрелок и «Сегодня» отдельные нативные кнопки без общей стеклянной обводки. Ползунок регулирует отдельный фон поверх материала, не прозрачность окна целиком. При системном уменьшении прозрачности фон становится непрозрачным; при уменьшении движения анимации отключаются. Темы: **Как в системе**, **Светлая**, **Темная**. Системная тема следует изменениям macOS. Управление использует системный акцент, цвета групп остаются пользовательскими.

На первом обычном запуске приложение один раз вызывает `SMAppService.mainApp.register()`. Это единственное предусмотренное взаимодействие с настройками запуска системы. Если требуется согласие, в панели и настройках появляется соответствующее состояние и кнопка открытия штатного раздела macOS. Приложение не подтверждает запрос за пользователя. Ошибки регистрации отображаются; автоматических повторных запросов после отключения нет.

Панель один раз показывается при первом запуске. Повторное открытие уже работающего приложения в Finder также показывает ее. Последующие запуски при входе остаются в строке меню без автоматически открытой панели.

Переключатель в настройках читает действительный статус ServiceManagement, обновляет его после возвращения в приложение и позволяет отключить автозапуск. Для ожидающего подтверждения запроса есть **Отменить запрос**. Локальная подпись, запуск из временного каталога и перемещение пакета могут влиять на регистрацию; при ошибке установите пакет в постоянное место и повторите включение. Фактический запуск при входе проверяется только выходом из учетной записи и повторным входом.

## Локальные данные и ограничения

У всех компонентов включён App Sandbox. Главный процесс поддерживает явно выбранную облачную синхронизацию с PWA через единственный HTTPS origin и работу с JSON, выбранными в системном диалоге. Сессия хранится в Keychain. Подробности — [MACOS_CLOUD.md](MACOS_CLOUD.md). Виджет остаётся без сетевых и файловых исключений; App Group служит только локальному обмену.

`ScheduleFetcher.xpc` имеет только исходящую сеть без App Groups/файловых исключений. Сохраняются HTTPS allowlist `www.istu.edu`, разрешённые пути расписания, запрет параметров/редиректов/cookies/кэша/JavaScript и предел ответа4МБ. Ручной режим — по умолчанию; автообновление1/3/6часов включается явно в настройках.

Каждое XPC-соединение обслуживает один GET. После ответа или отмены сеанс закрывается, а служба завершает процесс после отключения клиентов; есть предельный срок жизни. Основное приложение проверяет встроенную службу и привязывает XPC-соединение к ее code-signing requirement; в локальной ad hoc сборке это точный cdhash службы. Служба принимает соединения того же пользователя через частный XPC приложения. В сборке с Team требование к вызывающей стороне включает identifier основного приложения, Apple generic anchor и ту же Team; у локальной ad hoc подписи Team отсутствует, поэтому проверка вызывающей стороны ограничена identifier и тем же пользователем. Эта локальная конфигурация слабее проверки Team. Служба не читает и не проверяет весь пакет родительского приложения из своего sandbox. Сама XPC-служба не планирует фоновые запросы; автоматический режим организован контроллером приложения либо общим сервером. **Entitlement службы — статическое разрешение ОС на исходящую сеть, а не одноразовый сетевой токен.** Ограничение адресов и момента выполнения реализовано кодом службы и ее коротким жизненным циклом; App Sandbox сам по себе не ограничивает сеть одним доменом. Это заменяет прежнее абсолютное отсутствие сети в пакете новым явно запрошенным импортом. Устройство XPC и разрешения описаны в документации Apple: [Creating XPC services](https://developer.apple.com/documentation/xpc/creating-xpc-services), [Enabling App Sandbox](https://developer.apple.com/documentation/security/app_sandbox/enabling_app_sandbox), [Entitlement Key Reference](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html).

Приложение не использует аналитику, проверку обновлений, EventKit, браузер, LaunchAgents или shell-команды. Облако опционально, после входа; в ручном гостевом режиме фоновых запросов к вузу нет. Виджет запускает WidgetKit; XPC-службу запускает macOS по запросу приложения. Никаких запросов администратора, Accessibility, записи экрана или полного доступа к диску. Нет доступа к произвольным папкам; только файлы резервных копий, выбранные пользователем.

Локальная CLI-сборка сохраняет дела, группы и занятия в собственном контейнере приложения:

```text
~/Library/Containers/ru.local.GoldenGateCalendar/Data/Library/Application Support/ru.local.GoldenGateCalendar/
    planner.json
    planner.backup.json
```

Подписанная сборка с виджетом использует общий контейнер, который macOS возвращает для собственной App Group, обычно:

```text
~/Library/Group Containers/<AppGroupIdentifier>/Library/Application Support/Planner/
    planner.json
    planner.backup.json
    planner.lock
    widget-state.json
```

При первом открытии основного приложения его прежние `planner.json` и резервная копия переносятся в общий контейнер, если там еще нет базы. Перенос использует журнал завершения; исходные файлы сохраняются. Расширение не читает частный контейнер приложения и не импортирует его самостоятельно. Если настроенная App Group недоступна, ошибка показывается явно, без создания отдельной пустой базы виджета. После переноса CLI-вариант и подписанный вариант используют разные локальные хранилища; последующее переключение между ними не синхронизирует новые изменения автоматически.

Настройки панели, выбор института/группы/подгруппы, длительность, время последнего успешного импорта и кэш списков сохраняются через `UserDefaults` в собственном контейнере. Выбранная дата и вид панели не записываются: каждый обычный запуск начинается с сегодняшней даты и месяца. Дата виджета хранится отдельно в `widget-state.json`. Раздел **Без группы** не сохраняется как пользовательская группа; у его дел `groupID` отсутствует.

Хранилище — версионированный JSON: общая блокировка чтения/изменения, атомарная замена файла и резервная копия предыдущей корректной версии. Перед изменением приложение и расширение перечитывают последнюю версию, поэтому устаревший процесс не затирает новые дела. Изменения появляются в интерфейсе после успешного сохранения. При сбое записи пользователь видит ошибку. При повреждении основного файла восстанавливается **предыдущая** сохраненная версия, поврежденный файл сохраняется отдельно и показывается предупреждение. Если не читаются обе копии или формат создан более новой версией приложения, исходные файлы не перезаписываются и изменение данных блокируется. Это резервная копия от повреждения файла, а не история отмены действий.

Календарь использует григорианские даты и текущий часовой пояс Mac. Даты дел и занятий хранятся отдельными компонентами «год, месяц, день» и сохраняются при смене часового пояса; время занятия хранится как часы и минуты по расписанию. Формат JSON **4** содержит дела, группы, занятия, происхождение импортированных записей и отметки их ручного удаления. Он принимает прежние форматы **1**, **2** и **3**, сохраняя существующие данные; прежние занятия остаются ручными. В форматах 1 и 2 занятия изначально отсутствуют. Преобразование записывается при следующем успешном изменении, предыдущий файл сохраняется в резервной копии. Календарные расчеты используют `Calendar`, учитывая високосные годы и перевод часов. Текущий день обновляется по системным уведомлениям, пробуждению, открытию панели и резервному таймеру.

## Проверки

```sh
./scripts/test.sh
./scripts/validate-offline.sh build/Calendar.app
# Только исходная конфигурация, без заявления о проверке собранного пакета:
./scripts/validate-offline.sh --source-only
```

Первый скрипт проверяет календарные вычисления, операции с данными, сохранение/восстановление, настройки, расчет размещения кнопок, обратимую навигацию по группам, общее хранилище и расписание на изолированных данных. Для расписания проверяются валидация, сортировка, сводки, совместимость форматов 1/2/3/4, сохранность занятий при изменении дел из другого процесса, разбор HTML на fixtures, слияние импорта и ограничение запросов. Контроллер проверяется на подставной загрузке без сети. Скрипт не запускает обычное приложение и не регистрирует автозапуск. Второй проверяет конфигурацию, подпись и фактические разрешения **указанного** пакета: главный процесс с ограниченным CloudAPI и пользовательскими JSON, виджет без сети/файловых разрешений, отдельная XPC-служба только с исходящей сетью. Сетевые API главного процесса допускаются только в CloudAPI.swift; диагностический XPC host остаётся без сети. В Xcode-варианте аудит также учитывает встроенное расширение и совпадение App Groups. Имя `validate-offline.sh` сохранено для совместимости; скрипт не утверждает отсутствие сетевого компонента во всем пакете и сам не выполняет сетевых запросов. `--source-only` проверяет только исходные настройки. Ни один из этих шагов не заменяет запуск установленного WidgetKit-расширения и проверку без сети.

Подробные результаты и ограничения текущего окружения: [отчёт релиза](RELEASE_CHECKS.md). Ручные сценарии: [Ручная проверка.md](Ручная%20проверка.md).
