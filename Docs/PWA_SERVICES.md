# Сервисы для начала разработки SimpleSchedule PWA

Подготовлено 16 октября 2026. Это рекомендуемый набор; аккаунты, проекты, домены и платные услуги автоматически не создавались и не покупались.

Локальную разработку интерфейса/офлайнбазы можно начать без внешних аккаунтов. Для интеграции облачной синхронизации первым нужен Supabase; SMTP/домен — для реального входа по почте; Render — для публикации и серверного импорта.

| Сервис | Назначение | Что подготовить | Когда |
| --- | --- | --- | --- |
| GitHub | Код и сборки | Уже есть pouqwyggad1/SimpleSchedule; отдельный репозиторий не обязателен | Готово |
| Supabase | PostgreSQL, Auth, настройки аккаунта и журнал синхронизации | Аккаунт, организация и один проект simpleschedule-dev; надёжный пароль БД сохранить в менеджере паролей | До интеграции входа/синхронизации |
| Resend | Отправка одноразовых кодов входа | Аккаунт, подтверждённый отправляющий домен, SMTP-доступ; не включать tracking писем | До полноценного email OTP |
| Собственный домен/DNS | Верификация отправителя Resend | Любой уже принадлежащий домен или новый; доступ к DNS для записей, выданных Resend. Можно использовать поддомен auth | До полноценного email OTP |
| Render | ASP.NET Core API, импорт ИРНИТУ и файлы PWA | Создать аккаунт; Docker Web Service и GitHub-подключение настроить после появления кода/Dockerfile | До публикации/проверки с iPhone |

Предлагается один Render webservice: он обслуживает собранную React PWA и /api под одним адресом. Render даёт onrender.com и TLS; собственный домен именно для сайта можно подключить позже. Домен отправителя писем — отдельное требование Resend; адрес gmail.com/yandex.ru не заменяет владение доменом. Полноценный входящий почтовый ящик для no-reply не обязателен.

Настройка SMTP выполняется в панели Supabase Auth: host/port/username/password, адрес и имя отправителя, шаблон с кодом. Служебные ключи Resend, service_role/secretkey Supabase, пароль БД и серверные секреты не отправлять в чат и не публиковать в Git. Ввести их в защищённые настройки сервисов/локальный исключённый из Git конфиг при реализации. Для текущего этапа достаточно названий/ссылок созданных проектов и выбранного домена.

Отдельный cron-сервис не требуется: можно задействовать Supabase Cron/pg_net для вызова защищённого API и очереди заданий. Настройки/задачи добавлять после появления обработчика и его защиты. Альтернатива — планировщик выбранного хостинга.

Render Free подходит для тестов, но засыпает после 15 минут без входящего трафика; следующий запрос запускает сервис с задержкой. Для надёжного регулярного обновления и постоянного использования отдельно выбрать тариф/режим без такого ограничения. Не обещать бессрочную полностью бесплатную инфраструктуру. Встроенный SMTP Supabase предназначен для ограниченного тестирования на почтах участников проекта; для пользовательских кодов нужен свой SMTP.

Apple Developer, TestFlight и App Store для PWA не требуются. На старте не нужны отдельные Firebase, VPS, Vercel, Redis или Docker Hub: выбранные сервисы покрывают необходимые роли. Дальнейшие сервисы добавлять только при доказанной необходимости.
