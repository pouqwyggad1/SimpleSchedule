# Подключение Supabase, Resend и Render

Это инструкция по настройке подготовленного проекта. Созданный аккаунт сервиса сам по себе не подтверждает, что приложение подключено к нему. Не публикуйте секретные ключи и не отправляйте их в чат.

**Статус на 17 октября 2026 года:** PWA развёрнуто на Render: **https://simpleschedule-pwa.onrender.com**. Домен отправителя Resend подтверждён. Настройки Supabase Auth, оба русских шаблона писем и Custom SMTP сохранены; секретные переменные сервера заданы. На работающем сервере подтверждены вход и контрольный обмен между iPhone и браузером компьютера: создание дела, возврат выполнения и сохранение после перезагрузки. Проверка установки на главный экран и длительного фонового цикла ещё предстоит. Фактические результаты — в [CHECKS.md](CHECKS.md).

## 1. Supabase

В текущем проекте **SimpleSchedule** схема уже применена. Для новой установки сначала проверьте `PWA/supabase/schema.sql` в dev-проекте и убедитесь, что в целевой базе нет чужой рабочей схемы с теми же именами таблиц. Скрипт создаёт таблицы приложения, RLS, RPC синхронизации и закрытое хранилище сессий.

Для текущего проекта Project URL: `https://kofrjmkffcwkuuljdgez.supabase.co` (без `/rest/v1/`). Из настроек проекта понадобятся:

| Значение | Где используется |
| --- | --- |
| Project URL `https://….supabase.co` | `Supabase__Url` на сервере Render |
| Publishable key | `Supabase__PublishableKey` на сервере |
| Service role/secret server key | `Supabase__ServiceRoleKey`, только сервер; запрещён в клиенте |
| Случайный ключ AES, 32 байта в Base64 | `Session__EncryptionKey`, только сервер |

Создать ключ сессий можно локально командой `openssl rand -base64 32`, затем вставить результат в секретную переменную Render. Это не API-ключ Resend. Сохраните его в менеджере паролей; замена завершит существующие сессии.

В **Authentication → Sign In / Providers → Email** включите email-вход, вход по Magic Link / OTP и создание пользователей. Подтверждение email оставьте включённым. Выберите шестизначный код, срок действия **600 секунд (10 минут)** и минимальный интервал повторной отправки **60 секунд**; названия полей панели могут меняться.

Эти значения сохранены в текущем проекте; длина 6 цифр и срок 600 секунд повторно прочитаны в панели после сохранения пользователем.

В **Authentication → Notifications → Email** настройте **оба** шаблона: **Confirm sign up** и **Magic Link**. В обоих нужен код `{{ .Token }}`, а не только ссылка. При первом входе с новым адресом Supabase создаёт пользователя и отправляет письмо Confirm sign up; при последующих входах использует Magic Link. Тема обоих писем: **«Код входа в SimpleSchedule»**.

Полный русский шаблон находится в [emails/auth-code.html](emails/auth-code.html): UTF-8, одноразовый код, срок 10 минут, встроенные стили, без внешних ресурсов и отслеживания. Один и тот же HTML уже сохранён в обоих шаблонах Supabase; русская версия с кодом видна в их предварительном просмотре.

В **Authentication → URL Configuration** задайте Site URL **`https://simpleschedule-pwa.onrender.com`**. Для текущего входа по коду дополнительные redirect URLs не требуются; не добавляйте широкие шаблоны. Код API не получает доступ к почтовому ящику пользователя.

## 2. Resend и домен

В Resend уже подтверждён домен **`notify.pouqwyggad123.shop`**. Для приложения выбран отправитель **`SimpleSchedule <noreply@notify.pouqwyggad123.shop>`**. Четыре DNS-записи подтверждены; почтовый CNAME в Cloudflare использует **DNS only**, без HTTP-прокси. Существующие записи VPS и nameservers менять не требуется. Записи перечислены в [RESEND_DNS.md](RESEND_DNS.md).

После входа в панель Supabase откройте **Authentication → Notifications → Email → SMTP Settings**, включите **Custom SMTP** и заполните:

| Поле | Значение |
| --- | --- |
| Sender email | `noreply@notify.pouqwyggad123.shop` |
| Sender name | `SimpleSchedule` |
| Host | `smtp.resend.com` |
| Port | `465` — implicit SSL/TLS |
| Username | `resend` |
| Password | Существующий API-ключ Resend, вводится пользователем непосредственно в защищённое поле |
| Minimum interval per user | `60` секунд |

В текущем проекте **Custom SMTP включён**, настройки сохранены: `smtp.resend.com:465`, имя пользователя `resend`, указанный отправитель и скрытый сохранённый пароль. Доставка пользовательского письма подтверждена метаданными Resend; тестовые письма агент не отправлял. Для отдельного ключа ограничьте разрешение отправкой писем и доменом приложения, если это доступно. Не добавляйте ключ в репозиторий, `VITE_*`, скриншоты или чат. Отслеживание открытий и переходов для домена отправителя отключено и должно оставаться отключённым.

Отдельный купленный почтовый ящик `noreply` обычно не требуется для SMTP-отправки; DNS и подтверждение домена обязательны. Встроенная тестовая почта Supabase имеет ограничения по адресам и частоте, её нельзя представлять как готовую production-доставку.

Источники: [Supabase email OTP](https://supabase.com/docs/guides/auth/auth-email-passwordless), [шаблоны писем](https://supabase.com/docs/guides/auth/auth-email-templates), [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [настройка Resend SMTP в Supabase](https://resend.com/docs/send-with-supabase-smtp).

## 3. Render

Текущий Web Service **simpleschedule-pwa** уже развёрнут из `pouqwyggad1/SimpleSchedule`, ветка **pwa-ios**. Последнее развёртывание `dep-db93lft9fdbs738j5l8g` успешно, commit `87eccc2`. Публичный адрес: **https://simpleschedule-pwa.onrender.com**. Для новой установки можно использовать Blueprint **PWA/render.yaml** либо задать:

- Runtime: Docker.
- Root Directory: `PWA`.
- Dockerfile: `./Dockerfile`; Docker build context — корень выбранного каталога PWA.
- Health check: `/health`.
- Сервис слушает `0.0.0.0:8080`.
- Переменные Supabase и шифрования из таблицы выше; ничего из этого не добавлять в `VITE_*`.
- `PublicOrigin` — полный HTTPS-origin сервиса без конечного `/`, для проверки запросов на изменение данных.

Текущий сервис использует `onrender.com`; свой домен для самого сайта необязателен. Адрес сайта и домен отправителя писем — разные настройки. В действующем сервисе `PublicOrigin` установлен в `https://simpleschedule-pwa.onrender.com`.

Проверьте `/health`, открытие календаря, настройки и реальный цикл «код → вход → создать дело → войти на втором устройстве → получить дело». Затем проверьте выход и изоляцию другого аккаунта. Наличие зелёного статуса сборки не подтверждает доставку письма или RLS рабочего проекта.

План `free` указан для разработки. Он засыпает при простое; почасовой импорт и будущие своевременные push требуют работающего сервера либо надёжного внешнего планировщика. Не включайте платные ресурсы без выбранного вами тарифа.
