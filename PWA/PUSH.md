# Уведомления на iPhone

1. Откройте SimpleSchedule в Safari → «Поделиться» → «На экран “Домой”».
2. Запустите приложение с главного экрана и войдите с той же почтой, что на других устройствах.
3. Откройте **Настройки → Уведомления → Подключить уведомления** и разрешите их в окне iOS.
4. Включите **Включить уведомления**. Кнопка **Проверить уведомление** отправит одно проверочное сообщение на это устройство; повторная проверка доступна через минуту.

Разрешение и подписка отдельны на каждом устройстве. Общие предпочтения синхронизируются: напоминать перед занятием, сообщать об изменениях сайта, время в минутах, исключения по дисциплинам и датам. Значок колокольчика в выбранном дне включает тихий день. «Отключить это устройство» отзывает только текущую подписку; выход из аккаунта также прекращает отправку на него.

По умолчанию напоминание запланировано за 5 минут. Оно содержит предмет, аудиторию, преподавателя и вид занятия. Заметки, домашнее задание и почта в push не передаются. Нажатие открывает день расписания. Учитываются только общие занятия и выбранная подгруппа, а также выбранная учебная группа.

Изменения определяются по предыдущему снимку сайта: личное редактирование не вызывает сообщение «изменилось на сайте». Первый импорт создаёт исходный снимок без серии уведомлений. Неопубликованные даты не считаются отменой. После ручного обновления сначала должны синхронизироваться данные; в автоматическом режиме сервер сам обновляет снимок.

## Как это работает

- ASP.NET отправляет **Web Push с VAPID и aes128gcm** через `Lib.Net.Http.WebPush` 3.3.1. Секретный ключ хранится только в защищённых переменных сервера.
- Подписки, снимки источника и очередь доставки хранятся в Supabase; все три таблицы закрыты от `anon` и `authenticated`, включён RLS. Сервер устанавливает владельца из проверенной сессии, а заголовок аккаунта защищает от смены аккаунта в соседней вкладке.
- Планировщик Supabase Cron раз в минуту вызывает защищённый `/api/jobs/run` только при наличии фоновой работы. Токен берётся из Vault. Таймер не зависит от открытого iPhone. Работающий сервер также проверяет очередь каждые 30 секунд.
- Напоминания формируются по времени **Asia/Irkutsk**, независимо от часового пояса телефона. Перед отправкой повторно проверяются актуальное занятие, его отмена, подгруппа и все выключатели.
- Lease и уникальный ключ события защищают от параллельной обработки и обычных повторов. При ошибках сети/429/5xx есть ограниченные повторы; 404/410 удаляют истёкшую подписку. Абсолютная exactly-once доставка через внешнюю push-службу недостижима: при обрыве между принятием сообщения и записью результата возможен повтор; тег уведомления сворачивает его в системе.
- Срок хранения push ограничен началом пары, для изменений — максимум 6 часов. Просроченные напоминания не планируются задним числом. Уже доставленный push iOS обязана показать; если он пришёл поздно, обработчик заменяет устаревшие детали нейтральным приглашением открыть расписание.
- Service Worker кэширует оболочку приложения, но не `/api`, аккаунтные данные и ответы входа.

Сеть, режим фокусирования, энергосбережение и правила iOS могут задерживать доставку. Бесплатный Render может просыпаться после простоя и приостановиться при исчерпании общего бесплатного времени; платформа не обеспечивает точное время отправки. Новые платные сервисы не создавались. Результаты автоматических проверок не заменяют подтверждение на реальном iPhone.

## Настройка сервера

После `supabase/schema.sql` и существующих patches примените `supabase/migrations/*_web_push_notifications.sql`. Для новой установки используйте Supabase CLI migrations либо SQL Editor; не запускайте `mock-auth.sql` в рабочем проекте.

Один раз создайте пару ключей P-256: публичный ключ — uncompressed point (65 bytes, base64url без padding), приватный — scalar (32 bytes, base64url без padding). Сохраните **Push__PublicKey**, **Push__PrivateKey** в Render Environment. `PublicOrigin` должен быть основным HTTPS-адресом приложения. Не меняйте пару при каждом развёртывании: существующие браузерные подписки привязаны к ней.

В Supabase Vault сохраните тот же секрет, что у Render `Jobs__Secret`, с именем `simpleschedule_jobs_secret`. Примените `*_push_scheduler.sql`; перед использованием другого домена исправьте единственный URL `/api/jobs/run` в функции планировщика. Он не принимает Origin клиента, но требует отдельный секрет; все клиентские операции требуют обычный same-origin JSON-запрос и вход.

Проверка без чтения секретов: `/api/health` → `notificationsConfigured=true`, `/api/push/config` → только публичный ключ; Cron History → успешные minute ticks. Отправка в очередь видна по агрегатам `pwa_push_deliveries.status`, без вывода endpoint и содержимого сообщений в логи.

Остановить фоновую отправку: отключить общий переключатель, отозвать устройство либо отключить задание `simpleschedule-background-tick` в Supabase Cron. Для полного серверного отключения удалите защищённый `Push__PrivateKey` и перезапустите сервис. Сохранённые дела и расписание при этом не удаляются.
